- **API version:** `notify.weebo.io/v1alpha1`
- **Scope:** Namespaced
- **Short names:** `nak`
- **Guide:** [API keys](/docs/guides/api-keys)

An API key of a `NotifyServiceAccount`, minted by the operator through
the instance's key issuer and written to `secretTargets` as
`NOTIFY_API_KEY` (`wnk_…`) and `NOTIFY_URL`.

A key can't be read back: a lost target, a new
`notify.weebo.io/rotate-secret` value, or a change of the service
account, scopes or channels mints a new key. The new key is written to
every target before the previous one is revoked. Deleting the CR
revokes its key and deletes its targets; deleting the service account
revokes it too.

## Example

```yaml
apiVersion: notify.weebo.io/v1alpha1
kind: NotifyApiKey
metadata:
  name: my-apikey
  namespace: team-a
spec:
  serviceAccountRef:
    name: grafana
  scopes:
    - publish
  channels:
    - alerts
  secretTargets:
    - name: grafana-notify
```

## Spec fields

| Field | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `channels` | `string[]` | yes |  | The channel ids the key may act in.<br /><br />Constraints: `minItems: 1` |
| [`instanceRef`](#spec.instanceRef) | `object` | no |  | The instance: unset, the only one of this namespace. An instance of another namespace must accept this one (`objectSelector.namespaces`). |
| `scopes` | `string[]` | yes |  | What the key may do. Notify refuses a scope the service account doesn't hold in every channel listed.<br /><br />Values: `"publish"`, `"subscribe"`, `"manage"`<br /><br />Constraints: `minItems: 1` |
| [`secretTargets`](#spec.secretTargets) | `object[]` | no |  | Defaults to one target named after the CR, in its namespace, on the operator's default backend (`secretStore.defaultBackend` of its chart). A Vault target uses the operator's Vault connection and stays under `<pathPrefix>/<namespace>/`. |
| [`serviceAccountRef`](#spec.serviceAccountRef) | `object` | yes |  | The `NotifyServiceAccount` of this namespace the key acts as, bound to the same instance. |

### `spec.instanceRef` [#spec.instanceRef]

| Field | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `kind` | `string` | no |  | The kind of instance a reference designates.<br /><br />Values: `"Instance"`, `"LocalInstance"` |
| `name` | `string` | yes |  | `metadata.name` of the instance. |
| `namespace` | `string` | no |  | Namespace of a `LocalInstance`. Defaults to this object's own; required on a cluster-scoped object. Another namespace's local instance must share itself with this one (its `sharedWith`). |

**Rules**

- namespace only applies to kind LocalInstance — `!has(self.namespace) || !has(self.kind) || self.kind == 'LocalInstance'`

### `spec.secretTargets[]` [#spec.secretTargets]

| Field | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `backend` | `string` | no | `"kubernetes"` | `kubernetes` (default) or `vault`. A Vault target reuses the Vault connection (address, mount, auth) the instance configures, which it must then do.<br /><br />Values: `"kubernetes"`, `"vault"` |
| `name` | `string` | yes |  | Kubernetes: the `Secret` name. Vault: names the default path `<pathPrefix>/<namespace>/<name>` when `path` is unset. |
| `namespace` | `string` | no |  | Kubernetes `Secret` namespace (Vault: the namespace segment of the default path). Defaults to the CR's own namespace; required on cluster-scoped CRs. A namespaced CR may only name its own namespace. |
| `path` | `string` | no |  | Vault only: explicit KV v2 path under the instance's mount. It must stay under `<pathPrefix>/<namespace>/` (this object's namespace, or the target's on a cluster-scoped object), unless the instance's `pathGrants` open it to this object. |
